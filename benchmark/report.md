# Отчёт по эталонному тестированию промпта

## Методика

- Выборка: 50 синтетических текстовых резюме Java-разработчиков (`CV_051`–`CV_100`).
- Эталон: независимая оценка по отдельной рубрике моделью `gpt-6-astra` через Codex.
- Текущая система: оценка приложением через Proxy API и текущим `gpt-4o-mini`.
- Сравнение: 7 критериев, единая шкала 0–5, проверка цитат по исходному тексту.

## Результат

| Метрика | Эталон | Текущая система |
|---|---:|---:|
| Средний балл | 81.92 | 97.36 |
| Диапазон | 72–89 | 93–100 |
| Резюме с завышением | — | 49 из 50 |

Среднее завышение текущей системой составило **15.44 балла**. Основной источник расхождения — критерий «Дополнительные технологии»: модель часто считала краткое упоминание технологии полноценным подтверждением. Встречались также завышения по Java core, Spring/backend и тестированию, когда стек был перечислен без описания практического применения.

## Типичные ошибки

1. Список технологий трактовался как доказательство глубокой практики.
2. `Kafka` смешивалась с `Kafka Streams`; `Protobuf` — с `gRPC`; OpenAI API — с разработкой AI-агентов.
3. Упоминание версии Java или Spring повышало оценку Java core без сведений о JVM, многопоточности, коллекциях или производительности.
4. Отсутствие явной информации иногда превращалось в уверенное подтверждение.
5. Слабая граница между `partial` и `confirmed` приводила к завышению статуса.

## Что изменено в версии v2

Подготовлен `improved_system_prompt_v2.txt`. В него добавлены строгие правила для коротких непрерывных цитат, нулевой балл при отсутствии подтверждения, отдельные потолки для evidence только из стека и явное различение близких технологий. Исходный промпт сохранён в `system_prompt_before_v2.txt`.

Полные машинные результаты находятся в `comparison_report.json`, исходные оценки — в `reference_gpt6_astra.json` и `current_gpt4o_mini.json`.
